# CLAUDE.md - AI Assistant Notes for GUCEF Repository

This file contains important notes and reminders for AI assistants working on this codebase.

## Build System Notes

### CMake File Management

1. **Always update CMake files when adding/removing/renaming source files**
   - When adding new `.cpp` or `.h` files to a module, they must be registered in the module's CMake configuration
   - The build will succeed in Visual Studio (which uses `.vcxproj` files) but fail on CMake-based builds if files are not registered

2. **Where to find CMake file lists (IMPORTANT - follow this recipe)**
   
   The CMakeLists.txt file is located **directly in each module's directory**:
   - Platform libraries: `platform/<moduleName>/CMakeLists.txt`
   - Test applications: `tests/<testAppName>/CMakeLists.txt`
   - Plugins: `plugins/<category>/<pluginName>/CMakeLists.txt`
   - Tools: `tools/<toolName>/CMakeLists.txt`
   
   **Examples:**
   - `platform/gucefCORE/CMakeLists.txt` - for gucefCORE library
   - `tests/gucefCORE_TestApp/CMakeLists.txt` - for gucefCORE test app
   
   **Structure of these files:**
   ```cmake
   set( HEADER_FILES 
     include/SomeHeader.h
     include/AnotherHeader.h
   )
   
   set( SOURCE_FILES 
     src/SomeSource.cpp
     src/AnotherSource.cpp
   )
   ```
   
   **Recipe for adding/renaming/removing files:**
   1. Open `<moduleDir>/CMakeLists.txt` directly (don't search for other patterns)
   2. Find the `set( HEADER_FILES ...)` section for headers
   3. Find the `set( SOURCE_FILES ...)` section for sources
   4. Add/rename/remove the file entry with relative path (e.g., `include/MyFile.h` or `src/MyFile.cpp`)
   5. Files are listed alphabetically - maintain this order

3. **ProjectGenerator Tool**
   - These CMakeLists.txt files were originally generated by `ProjectGenerator` tool
   - The tool may regenerate them, but manual edits to file lists are common

4. **Do NOT manually edit Visual Studio project files**
   - Visual Studio project files (`.vcxproj`, `.vcxproj.filters`, `.sln`) are **generated from CMake**
   - Do not manually edit these files to add/remove source files
   - Instead, edit the CMake files and run a build
   - The build process will regenerate the Visual Studio project files
   - After regeneration, Visual Studio will prompt to reload the modified project files

### Module Locations

- Platform libraries: `platform/<moduleName>/`
- Test applications: `tests/<testAppName>/`
- Plugins: `plugins/<category>/<pluginName>/`
- Tools: `tools/<toolName>/`
- Dependencies: `dependencies/<depName>/`

## Code Style Notes

### File Naming Conventions

- Header files: `gucefCORE_CClassName.h` (module prefix + class name)
- Source files: `gucefCORE_CClassName.cpp` (matching header name)
- Test files: `TestClassName.h` / `TestClassName.cpp`

### Include Guard Pattern

```cpp
#ifndef GUCEF_CORE_CCLASSNAME_H
#define GUCEF_CORE_CCLASSNAME_H
// ... content ...
#endif /* GUCEF_CORE_CCLASSNAME_H ? */
```

### Include Pattern

```cpp
#ifndef GUCEF_CORE_SOMEFILE_H
#include "gucefCORE_SomeFile.h"
#define GUCEF_CORE_SOMEFILE_H
#endif /* GUCEF_CORE_SOMEFILE_H ? */
```

### Namespace Pattern

```cpp
namespace GUCEF {
namespace CORE {
// ... content ...
}; /* namespace CORE */
}; /* namespace GUCEF */
```

### Tracing

- Add `{GUCEF_TRACE;` at the start of function bodies for tracing support

### Logging

- **Always use GUCEF logging macros**, not `std::cout` or other direct output
- The GUCEF logging system directs output to the appropriate logging outputs based on platform and application preferences
- Common logging macros (from `gucefCORE_Logging.h` / `gucefCORE_LoggingMacros.h`):
  - `GUCEF_LOG( logLevel, message )` - General logging
  - `GUCEF_DEBUG_LOG( logLevel, message )` - Debug-only logging
  - `GUCEF_ERROR_LOG( logLevel, message )` - Error logging
  - `GUCEF_WARNING_LOG( logLevel, message )` - Warning logging
- Log levels: `LOGLEVEL_CRITICAL`, `LOGLEVEL_NORMAL`, `LOGLEVEL_BELOW_NORMAL`, `LOGLEVEL_EVERYTHING`

### C++ Feature Compatibility Macros

The codebase supports older C++ compilers. Use these macros from `gucef_cpp.h`:

- **Move semantics**: Use `#ifdef GUCEF_MOVE_SEMANTICS_SUPPORTED` to guard move constructors and move assignment operators
  - Use `GUCEF_MOVE( m )` instead of `std::move( m )` - it falls back gracefully on older compilers
  - Some older code may use `GUCEF_RVALUE_REFERENCES_SUPPORTED` (equivalent, but prefer `GUCEF_MOVE_SEMANTICS_SUPPORTED` for new code)
- **noexcept**: Use `GUCEF_NOEXCEPT` instead of `noexcept`
- **override**: Use `GUCEF_VIRTUAL_OVERRIDE` instead of `override`

Example:
```cpp
class MyClass
{
    #ifdef GUCEF_MOVE_SEMANTICS_SUPPORTED
    MyClass( MyClass&& src ) GUCEF_NOEXCEPT;
    MyClass& operator=( MyClass&& src ) GUCEF_NOEXCEPT;
    #endif
};

// In implementation:
#ifdef GUCEF_MOVE_SEMANTICS_SUPPORTED
MyClass::MyClass( MyClass&& src ) GUCEF_NOEXCEPT
    : m_member( GUCEF_MOVE( src.m_member ) )
{GUCEF_TRACE;
}
#endif
```
