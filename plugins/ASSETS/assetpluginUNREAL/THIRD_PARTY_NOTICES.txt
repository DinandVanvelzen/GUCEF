assetpluginUNREAL: third party notices
======================================

assetpluginUNREAL is licensed under the Apache License, Version 2.0 (see LICENSE.txt in the root of the repository).
The package and property readers of this plugin are written in C++98 for GUCEF. Where they follow the decisions of the
permissive readers named below closely, this is stated here, with the licence text of the project followed.

No code of the Unreal Engine was read. No GPL, LGPL or AGPL reader (UEViewer/umodel, the parts of FModel that are its own,
UAssetReader) was read. The sources below were read through their public repositories only (nothing was cloned, built or run).


1. CUE4Parse
------------

Project:   CUE4Parse, https://github.com/FabianFG/CUE4Parse
Licence:   Apache License, Version 2.0 (text below). The licence file of the project holds the standard text and names no holder;
           the copyright belongs to the authors of CUE4Parse.

What follows it (field order, version conditions and flag values; the C++ is written independently):

  * assetpluginUNREAL_CUnrealPackageSummary.cpp   the order of the fields of the package summary and the file version that
                                                  introduces each of them (FPackageFileSummary.cs)
  * assetpluginUNREAL_CUnrealObjectImport.cpp,
    assetpluginUNREAL_CUnrealObjectExport.cpp,
    assetpluginUNREAL_CUnrealPackageIndex.cpp     the fields and version conditions of import and export entries and the meaning
                                                  of the package index (ObjectResource.cs)
  * assetpluginUNREAL_CUnrealPropertyTag.cpp,
    assetpluginUNREAL_CUnrealPropertyTypeName.cpp the two tag layouts, the values of the tag flags and tag extensions, the
                                                  pre-order encoding of the type name tree and the rule that a value is always
                                                  followed by a seek to the declared end (FPropertyTag.cs)
  * assetpluginUNREAL_CUnrealSkeletalMeshReader.cpp,
    assetpluginUNREAL_CUnrealReferenceSkeleton.cpp,
    assetpluginUNREAL_CUnrealSkeletonReader.cpp  the order of the fields of a skeletal mesh (strip flags, imported bounds, material
                                                  slots, reference skeleton, the editor LOD models with their sections, soft vertices,
                                                  indices and bone lists) and the version conditions of the fields of sections, vertices
                                                  and source section user data (USkeletalMesh.cs, FStaticLODModel.cs, FSkelMeshSection.cs,
                                                  FSoftVertex.cs, FSkelMeshSourceSectionUserData.cs, FReferenceSkeleton.cs); the fields
                                                  whose presence differs between engine releases (texture streaming data of a material
                                                  slot, ray tracing flag, weight precision, strip flags of the model, cloth mapping lists)
                                                  were determined on the samples of 5.3, 5.6 and 5.8
  * assetpluginUNREAL_UnrealVersions.h            the names of the file version values (the values are those of the engine file
                                                  version history as used by the readers)

Verified on the samples of the local corpus (editor packages of engine releases 4.14, 5.3, 5.6 and 5.8: 43 skeletal meshes of 5.3, the
skeletal meshes of the MetaHuman packages of 5.6 and 5.8, and the material instances and master materials of the three).


2. UAssetAPI
------------

Project:   UAssetAPI, https://github.com/atenfyr/UAssetAPI
Licence:   MIT (text below)
Copyright: Copyright (c) 2020 - 2026 atenfyr

What follows it: the names of the custom versions in assetpluginUNREAL_CUnrealCustomVersionIds.cpp are the names of its custom
version table (consulted for the design survey). No source code of UAssetAPI was read for the implementation.


3. Written from the samples
---------------------------

The package trailer (assetpluginUNREAL_CUnrealPackageTrailer.cpp), the 48 byte editor bulk data record
(assetpluginUNREAL_CUnrealEditorBulkData.cpp), the compressed buffer header (assetpluginUNREAL_CUnrealCompressedBufferHeader.cpp),
the legacy bulk data header and the decoders of the binary structs were written from measurements of the sample packages and
the description in the design document; the tests check them against those packages. The layout of the data resource table is
not decoded (only its size is read): no sample holds one.

The Oodle tool
--------------

Payloads that are compressed with Oodle (UE 5 texture sources and mesh descriptions) are decompressed by the separate program
"ooz_extract" (dependencies/ooz in this repository, GPL-3.0-or-later, based on "ooz" by Powzix, see dependencies/ooz/README.txt and
its COPYING). The plugin never links it and contains none of its code: COodleToolProvider starts it as a child process and exchanges plain
bytes with it through files and the standard input and output. The plugin stays under the Apache License 2.0. A host that ships the
tool next to its executable ships its licence text and the pointer to its source with it.

The layout of the mesh description payload (CUnrealMeshDescription) and the use of the CRC-32 for the header of compressed buffers are
derived from the owned sample packages, which describe themselves; no source code of the engine or of another reader was used for them.
